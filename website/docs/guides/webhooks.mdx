# Webhooks

The API server calls webhooks over HTTPS. petri generates a webhook CA for each
control plane, and gives you what a local webhook server needs to work with it:
a serving certificate the API server trusts, and installers that point your
webhook configurations at your server.

## Admission webhooks

<CodeBlock language="yaml" title="testdata/manifests.yaml">{Manifests}</CodeBlock>

- `cp.ServingCertDir(t)` writes `tls.crt` and `tls.key` for `127.0.0.1` and
  `localhost`, signed by the plane's CA. A controller-runtime webhook server
  can load them as they are through its `CertDir` option. The directory is
  removed with the test. It is the only thing petri writes to disk.
- `cp.InstallAdmissionWebhooks(t, options, sources...)` installs the mutating
  and validating webhook configurations it finds in its sources, which work as
  in [InstallCRDs](crds.mdx). It points each service-based webhook at
  `options.Host` and `options.Port`, keeps its path, and sets the plane's CA as
  its `caBundle`.
- Each configuration gets a unique name and is deleted when the test ends, so
  parallel tests can install the same manifests.
- `options.Namespace` limits every webhook to one namespace, on top of any
  selector the manifest already has. Leave it empty only for webhooks that
  must see the whole cluster: on the shared plane, a webhook without a
  namespace fires for every test's objects.
- [`cp.WebhookCABundle()`](https://pkg.go.dev/github.com/yyewolf/petri#ControlPlane.WebhookCABundle) returns the CA, for configurations that set their own
  URL.

The API server finds new webhook configurations through a watch, so the first
requests after installing may miss the webhook. Retry the first request that
depends on it, as the example does.

## Conversion webhooks

First install the CRDs, with the `conversion.webhook` section your project
generates. Then call
[`cp.InstallConversionWebhooks`](https://pkg.go.dev/github.com/yyewolf/petri#ControlPlane.InstallConversionWebhooks)
with the CRD names and a `petri.ConversionWebhookOptions{Host, Port}`. It
points each named CRD's conversion webhook at your server, keeps the path, and
sets the plane's CA as the `caBundle`. It leaves alone CRDs whose webhook sets
its own URL.

A CRD applies to the whole plane, so the shared plane refuses conversion
webhooks. Use a [dedicated plane](control-planes.mdx#dedicated-control-planes).

## Without a testing.T

[`InstallAdmissionWebhooksCtx`](https://pkg.go.dev/github.com/yyewolf/petri#ControlPlane.InstallAdmissionWebhooksCtx) returns an error and a cleanup function that
removes the configurations. [`InstallConversionWebhooksCtx`](https://pkg.go.dev/github.com/yyewolf/petri#ControlPlane.InstallConversionWebhooksCtx) returns an error.
[`WriteServingCert(dir)`](https://pkg.go.dev/github.com/yyewolf/petri#ControlPlane.WriteServingCert) writes the certificate and key to a directory you manage.
