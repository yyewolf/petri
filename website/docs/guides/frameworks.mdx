# Ginkgo and other frameworks

## Ginkgo

Ginkgo's `GinkgoTB()` adapts the running spec to a `testing.TB`, so petri's
helpers work in specs as they do in plain tests, the shared plane included.
Cleanups petri registers, such as deleting the test's namespace, run when the
spec ends.

[envtest drop-in](migrating-from-envtest.mdx) and keep the suite as it is.

## Without a testing.TB

For frameworks that cannot provide a `testing.TB`, most helpers have a variant
that takes a context and returns an error:

| With a `testing.TB` | Context variant |
|---|---|
| `petri.Start(t)` | `petri.New(ctx)`, then `Stop` |
| `cp.Namespace(t)` | `cp.NewNamespace(ctx)`; you delete it |
| `cp.InstallCRDs(t, ...)` | `cp.InstallCRDsCtx(ctx, ...)` |
| `cp.InstallAdmissionWebhooks(t, ...)` | `cp.InstallAdmissionWebhooksCtx(ctx, ...)`, which returns a cleanup |
| `petri.WaitFor(t, ...)` | `petri.WaitUntil(ctx, ...)` |
| `petri.Retry(t, ...)` | `petri.RetryUntil(ctx, ...)` |
| `cp.AddNode(t, ...)` | `cp.AddNodeCtx(ctx, ...)`; you delete it |
| `node.Drain(t)`, `node.Cordon(t)`, … | `node.DrainCtx(ctx)`, `node.CordonCtx(ctx)`, … |
| `cp.Bind(t, ...)`, `cp.Evict(t, ...)`, … | `cp.BindCtx(ctx, ...)`, `cp.EvictCtx(ctx, ...)`, … |
| `cp.ExpectPod(t, ...)` | `cp.ExpectPodCtx(ctx, ...)` |
| `cp.ExpectPods(t, ...)` | `cp.ExpectPodsCtx(ctx, ...)`, then `Verify(ctx)` |
| `cp.StrictPods(t)` | `cp.StrictPodsCtx(ctx)`, then `cp.UnexpectedPods()` |

`cp.EnableControllers` has no context variant: it needs a `testing.TB`. The
shared plane does too; without one, start a dedicated plane with `petri.New`.
The context variants leave cleanup to you.
