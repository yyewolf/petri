# Migrating from envtest

`github.com/yyewolf/petri/controllerruntime/envtest` is a drop-in replacement
for controller-runtime's `envtest` package. In a kubebuilder project, change
the import in `suite_test.go` and nothing else:

```diff
- "sigs.k8s.io/controller-runtime/pkg/envtest"
+ "github.com/yyewolf/petri/controllerruntime/envtest"
```

<CodeBlock language="go" title="suite_test.go">{Suite}</CodeBlock>

You can then remove the `setup-envtest` step from your Makefile and CI,
`KUBEBUILDER_ASSETS`, and any cache of downloaded binaries.

## What Start does

`Environment.Start` starts a dedicated control plane and installs the CRDs and
webhook configurations. Like envtest, it fills in `LocalServingHost`,
`LocalServingPort` and `LocalServingCertDir` for your webhook server. `Stop`
removes the webhook configurations and the certificate directory, then stops
the plane.

Supported fields: `CRDDirectoryPaths`, `CRDs`, `ErrorIfCRDPathMissing`,
`CRDInstallOptions.Paths`, `CRDInstallOptions.CRDs`,
`WebhookInstallOptions.Paths`, `WebhookInstallOptions.MutatingWebhooks`,
`WebhookInstallOptions.ValidatingWebhooks`,
`WebhookInstallOptions.LocalServingHost`, `WebhookInstallOptions.LocalServingPort`,
`WebhookInstallOptions.LocalServingCertDir`, `Scheme`,
`AttachControlPlaneOutput` and `DisableDefaultControllers`.

Some fields would change what your tests check, so `Start` fails when they are
set instead of ignoring them:

- `UseExistingCluster`: petri never talks to a real cluster;
- `BinaryAssetsDirectory`: petri runs no binaries;
- `CRDInstallOptions.CleanUpAfterUse`: petri never deletes CRDs.

A CRD path that is missing or has no manifests always fails, whatever
`ErrorIfCRDPathMissing` says.

## What changes

The drop-in runs petri's default controllers, the namespace controller and the
garbage collector, so your suite sees what a cluster would do:

<CodeBlock language="go" title="namespace_test.go">{Spec}</CodeBlock>

| | envtest | petri |
|---|---|---|
| Deleted namespace | stays `Terminating` | removed |
| Deleting an owner | dependents stay | dependents deleted |
| Binaries | kube-apiserver and etcd, downloaded | none, compiled in |
| Kubernetes version | any, per binary | your `k8s.io/client-go` minor |
| Workload controllers | none | opt-in with `testEnv.EnableControllers(t, ...)` |

A test that relied on envtest's behaviour may notice. The usual case is a
custom resource with a finalizer that nothing removes: its namespace now stays
`Terminating` until the finalizer goes, as on a cluster. Remove the finalizer
in the test's cleanup, or set `DisableDefaultControllers: true` to get
envtest's behaviour back.

petri cannot test version skew, such as your client against an older API
server; see [compatibility](../reference/compatibility.mdx#one-version-per-test-binary).
