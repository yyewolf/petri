# Migrating from envtest

`github.com/yyewolf/petri/controllerruntime/envtest` is a drop-in for
controller-runtime's `envtest` package. In a kubebuilder project, change the
import in `suite_test.go` and nothing else:

```diff
- "sigs.k8s.io/controller-runtime/pkg/envtest"
+ "github.com/yyewolf/petri/controllerruntime/envtest"
```

<CodeBlock language="go" title="suite_test.go">{Suite}</CodeBlock>

Then remove what petri makes unnecessary: the `setup-envtest` step in your
Makefile and CI, `KUBEBUILDER_ASSETS`, and any cache of downloaded binaries.

## What Start does

`Environment.Start` runs a dedicated control plane, installs the CRDs and the
webhook configurations, and fills in `LocalServingHost`, `LocalServingPort`
and `LocalServingCertDir` for your webhook server, as envtest does. `Stop`
removes the installed webhook configurations and the certificate directory,
and stops the plane.

Supported fields: `CRDDirectoryPaths`, `CRDs`, `ErrorIfCRDPathMissing`,
`CRDInstallOptions.Paths`, `CRDInstallOptions.CRDs`,
`WebhookInstallOptions.Paths`, `WebhookInstallOptions.MutatingWebhooks`,
`WebhookInstallOptions.ValidatingWebhooks`,
`WebhookInstallOptions.LocalServingHost`, `WebhookInstallOptions.LocalServingPort`,
`WebhookInstallOptions.LocalServingCertDir`, `Scheme`,
`AttachControlPlaneOutput` and `DisableDefaultControllers`.

Fields that would change what a test tests make `Start` fail instead of being
ignored:

- `UseExistingCluster`: petri never talks to a real cluster;
- `BinaryAssetsDirectory`: petri runs no binaries;
- `CRDInstallOptions.CleanUpAfterUse`: petri never deletes CRDs.

A CRD path that is missing or holds no manifests always fails, whatever
`ErrorIfCRDPathMissing` says.

## What changes

The drop-in runs petri's default controllers, the namespace controller and the
garbage collector, so your suite now sees what a cluster would:

<CodeBlock language="go" title="namespace_test.go">{Spec}</CodeBlock>

| | envtest | petri |
|---|---|---|
| Deleted namespace | stays `Terminating` | removed |
| Deleting an owner | dependents stay | dependents deleted |
| Binaries | kube-apiserver and etcd, downloaded | none, compiled in |
| Kubernetes version | any, per binary | your `k8s.io/client-go` minor |
| Workload controllers | none | opt-in with `testEnv.EnableControllers(t, ...)` |

A test that relied on envtest's behaviour can notice. The usual case is a
custom resource with a finalizer nobody removes: its namespace now stays
`Terminating`, waiting for that object, as it would on a cluster. Remove the
finalizer in the test's cleanup, or set `DisableDefaultControllers: true` for
envtest's behaviour.

Version-skew testing, running your client against an older or newer API
server, is not possible with petri: the API server is compiled into the test
binary, so it always matches your client libraries.
