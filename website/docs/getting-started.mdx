# Getting started

## Install

```bash
go get github.com/yyewolf/petri@v0.37
```

petri needs Go 1.26 or newer, the same as Kubernetes 1.37.

Pick the petri minor that matches your `k8s.io/client-go` minor. A test binary
can link only one API server, and it is built from the same Kubernetes
release as your client libraries:

| petri     | Kubernetes | `k8s.io/client-go` |
|-----------|------------|--------------------|
| `v0.37.x` | 1.37       | `v0.37.x`          |

controller-runtime works with petri as it is: pass `cp.Config()` to
`ctrl.NewManager`. The optional sub-module adds a drop-in replacement for
envtest and a few test helpers; see
[controller-runtime](guides/controller-runtime.mdx). To use it:

```bash
go get github.com/yyewolf/petri/controllerruntime@v0.37
```

## A first test

<CodeBlock language="go" title="quickstart_test.go">{Quickstart}</CodeBlock>

- `petri.Start(t)` returns the control plane that every test in the binary
  shares, and starts it on first use. You set nothing up in `TestMain` and
  tear nothing down.
- `cp.Namespace(t)` gives the test its own namespace, so parallel tests do not
  see each other's objects. The namespace is deleted when the test ends.
- `cp.Client()` and `cp.Config()` give admin access, like envtest's config.
- The namespace controller and the garbage collector always run. A test
  enables any other controller it needs, such as the Deployment controller
  here, with `EnableControllers`.
- `petri.WaitFor` watches the object until the condition holds. It fails the
  test after 30 seconds.

## Run it

```bash
go test ./...
```

The first build compiles the API server and takes a few minutes. Later runs
use Go's build cache. Builds with `-race` need much more memory than with
envtest, because the race detector instruments the API server too; see
[resource usage](reference/resource-usage.mdx).
