# CRDs

`cp.InstallCRDs(t, sources...)` installs CustomResourceDefinitions. It returns
once each CRD is `Established` and discovery serves its resources, so a
RESTMapper or client built right after it already knows the new kinds.

## Sources

A source can be:

- a path to a file, or to a directory that is read recursively;
- an `fs.FS`, such as manifests embedded with `//go:embed`;
- a `*apiextensionsv1.CustomResourceDefinition` object.

Files can be YAML or JSON, with several documents per file. Documents that are
not CRDs are skipped, as in envtest, so you can point it at a directory of
mixed manifests such as kubebuilder's `config/crd/bases`.

## Installing from many tests

Call `InstallCRDs` in each test that needs the CRDs, not once in `TestMain`.
Parallel tests can install the same CRDs safely:

- a CRD that does not exist yet is created;
- a CRD that exists with the same spec, after the API server's defaulting, is
  left alone;
- a CRD that exists with a different spec fails the test and shows the diff.

CRDs are never deleted, because other tests on the shared plane may still use
them.

The namespace controller and the garbage collector handle custom resources

removes them, and their owner references cascade.
